# CLAUDE.md 行为指南摘要

## 核心要点

CLAUDE.md 是一份旨在减少 LLM 编码常见错误的指南，基于 Andrej Karpathy 的观察总结。该指南包含四个核心原则，强调**谨慎优先于速度**的权衡。

### 1. 编码前思考
**不要假设。不要隐藏困惑。呈现权衡。**
- 明确陈述假设，如果不确定就提问
- 当存在多种解释时，呈现所有可能性而不是默默选择
- 如果存在更简单的方法，说出来
- 遇到不清楚的地方要停下来，指出困惑点并提问

### 2. 简洁优先
**用最少的代码解决问题。不要过度推测。**
- 不添加要求之外的功能
- 不为一次性代码创建抽象
- 不添加未要求的"灵活性"或"可配置性"
- 不为不可能发生的场景做错误处理
- 如果 200 行代码可以写成 50 行，就重写它
- **检验标准**：资深工程师会觉得这过于复杂吗？

### 3. 精准修改
**只碰必须碰的。只清理自己造成的混乱。**
- 不"改进"相邻的代码、注释或格式
- 不重构没坏的东西
- 匹配现有风格，即使你倾向于不同的写法
- 如果注意到无关的死代码，提一下但不要删除
- 删除因你的改动而变得无用的导入/变量/函数
- **检验标准**：每一行修改都应该能直接追溯到用户的请求

### 4. 目标驱动执行
**定义成功标准。循环验证直到达成。**
- 将指令式任务转化为可验证的目标
- 对于多步骤任务，说明简短的计划
- 强有力的成功标准让 LLM 能够独立循环执行

## 关键数据
- 指南源自 Andrej Karpathy 对 LLM 编码陷阱的观察
- 包含四个原则，每个原则解决特定的 LLM 编码问题
- 设计用于与项目特定指令合并
- 对于琐碎任务需要自行判断，指南倾向于谨慎而非速度

## 安装方式
1. **Claude Code 插件**（推荐）：通过插件市场安装
2. **CLAUDE.md 文件**：按项目添加，可下载或追加到现有文件

## 如何判断指南在起作用
- diff 中不必要的改动更少
- 因过度复杂而导致的重写更少
- 澄清问题在实现之前提出
- 干净、精简的 PR，没有顺带的重构或"改进"
