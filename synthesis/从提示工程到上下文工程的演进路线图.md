## 概述

本文档梳理从**提示工程（Prompt Engineering）**到**上下文工程（Context Engineering）**的演进历程，分析各阶段的核心特征、技术要点和代表性实践。这条演进路径反映了 AI 应用从简单的指令优化，逐步发展为复杂的智能体系统的技术演变。

---

## 第一阶段：基础提示工程

### 核心特征
- 关注**词句技巧和表达方式**
- 作用范围仅限于**任务描述的表达**
- 类比：像贴一张便签

### 关键要素
根据 [Elements of a Prompt](sources/elements-of-a-prompt.md)，提示词通常包含四要素：
- **Instruction（指令）**：希望模型执行的特定任务
- **Context（上下文）**：外部信息或额外背景
- **Input Data（输入数据）**：我们感兴趣的问题
- **Output Indicator（输出指示器）**：输出的类型或格式

### 最佳实践
[OpenAI 最佳实践](sources/best-practices-prompt-engineering-openai.md) 提供了 9 条核心规则：
1. 使用最新模型
2. 指令放在开头，使用 ### 或 """ 分隔
3. 具体、描述性且尽可能详细
4. 通过示例说明期望的输出格式
5. 从 zero-shot → few-shot → 微调
6. 减少冗长和不精确的描述
7. 说应该做什么，而非不做什么
8. 代码生成使用 "leading words"
9. 使用 Generate Anything 特性

### 局限性
- 静态、一次性、依赖人类编写
- 缺乏动态适应性
- 无法处理长时任务和复杂工作流

## 第二阶段：结构化提示词

### 核心特征
- 将提示词组织为**标准化的模块化结构**
- 支持 Markdown/YAML 语法
- 可在运行时调整变量并立即生效

### 常用模块
[结构化提示词](sources/如何写好prompt-结构化.md) 包含：
- **Role**：指定角色，让模型聚焦对应领域
- **Profile**：作者、版本、描述
- **Goals**：一句话描述 Prompt 目标
- **Constrains**：限制条件，帮模型"剪枝"
- **Skills**：强化领域信息权重
- **Workflow**：指定对话和输出方式
- **Initialization**：冷启动对白

### 代表实践
[LangGPT](sources/结构化提示词知识库.md) 作为国内最大结构化提示词社区，推动了模块化提示词的普及，被百度、智谱、字节、华为等主流平台采用。

## 第三阶段：函数调用与 Agent 基础

### 核心特征
- 赋予 LLM **与外部系统交互的能力**
- 模型可以调用外部函数获取信息
- 从"内容生成器"升级为"任务执行器"

### 技术实现
[Function Calling](sources/function-calling-openai-api.md) 提供：
- 工具定义（JSON Schema）
- 工具调用请求
- 函数执行与结果回传
- 多轮对话循环

### Agent 架构
[LangChain Agent](sources/大模型应用开发框架-langchain-学习笔记-二.md) 定义了核心概念：
- **Tools**：希望 Agent 执行的函数
- **Agent**：理解问题并选择工具
- **Agent Executor**：递归调用直到任务完成

### 代表模式：ReAct
[ReAct (Reasoning + Acting)](sources/ai-agent-主流设计模式.md) 是最早且最重要的 Agent 设计模式：
- **Thought**：分析任务、制定计划
- **Action**：调用外部工具
- **Observation**：获取环境反馈
- 循环执行直到任务完成

优势：与现实世界反馈结合，减少幻觉
挑战：每次调用都需要 LLM 推理，Token 消耗高

## 第四阶段：Agent 设计模式演进

### 规划类模式
| 模式 | 核心思想 | 适用场景 |
|------|----------|----------|
| **Plan & Execute** | 先规划后执行，Planner 生成计划，Executor 执行 | 需要全局思考的复杂任务 |
| **REWOO** | 一次性生成包含变量的完整计划 | 工具间需要数据传递 |
| **LLM Compiler** | 生成任务 DAG，并行执行 | 需要同时获取多项独立信息 |

### 反思类模式
| 模式 | 核心思想 | 适用场景 |
|------|----------|----------|
| **Basic Reflection** | 任务完成后显式反思和批判 | 迭代优化的创作/编程 |
| **Reflexion** | 跨试验的试错学习，动态记忆 | 需要从失败中学习的复杂任务 |
| **LATS** | 结合树搜索、ReAct、Plan & Solve、反思 | 深度探索和多维度决策 |

### 演进逻辑
```
效率优化路线：ReAct → Plan & Execute → REWOO → LLM Compiler
            （核心：减少 Token 消耗和执行延迟）

反思增强路线：ReAct → Basic Reflection → Reflexion → LATS
            （核心：减少幻觉和探索更优路径）
```

## 第五阶段：上下文工程

### 定义
[上下文工程](sources/浅谈上下文工程.md) 是构建动态系统，以合适的格式为大语言模型提供正确的信息和工具，让其合理完成任务。

上下文不仅指单一提示词，更是模型在生成响应前看到的一切信息。

### 提示工程 vs 上下文工程
| 对比维度 | 提示工程 | 上下文工程 |
|----------|----------|------------|
| 关注点 | 词句技巧和表达方式 | 提供全面上下文 |
| 作用范围 | 限于任务描述的表达 | 包含文档、示例、规则、模式、验证 |
| 类比 | 像贴一张便签 | 像写一部详细剧本 |

### 长上下文的问题
[LangChain 上下文工程](sources/context-engineering.md) 指出四大问题：
- **Context Poisoning**：幻觉进入上下文
- **Context Distraction**：上下文压倒训练
- **Context Confusion**：冗余上下文影响响应
- **Context Clash**：上下文各部分不一致

### 四大策略
[Anthropic 官方实践](sources/effective-context-engineering-ai-agents.md)：

1. **Write Context（写入）**：将信息保存到上下文窗口外
   - Scratchpads：便笺式记录
   - Memories：跨会话记忆

2. **Select Context（选择）**：将相关信息拉入上下文
   - RAG：检索增强生成
   - 工具选择：RAG 应用到工具描述

3. **Compress Context（压缩）**：仅保留所需 tokens
   - Context Summarization：总结累积交互
   - Context Trimming：硬编码启发式过滤

4. **Isolate Context（隔离）**：拆分上下文
   - Multi-agent：跨子智能体拆分
   - Sandbox：沙盒隔离
   - State：运行时状态隔离

### 长时任务技术
- **Compaction**：压缩对话内容，用摘要重新初始化
- **Structured Note-taking**：智能体定期写笔记到外部内存
- **Sub-agent Architectures**：专门子智能体处理专注任务

## 第六阶段：Agent Skills 与能力扩展

### 核心概念
[Agent Skills](sources/agent-skills-overview.md) 是轻量级、开放格式的规范，用于为 AI 智能体扩展专业能力和工作流。

一个 Skill 是包含 `SKILL.md` 文件的文件夹，包含元数据和执行任务的指令，可捆绑脚本、参考资料等资源。

### 渐进式披露架构
[官方文档](sources/agent-skills.md) 定义三级加载：

| Level | 加载时机 | Token 成本 | 内容 |
|-------|----------|------------|------|
| **Level 1** | 始终（启动时） | ~100 tokens/Skill | name + description |
| **Level 2** | 触发时 | < 5k tokens | SKILL.md 主体 |
| **Level 3+** | 按需 | Effectively unlimited | 捆绑文件，bash 执行 |

### 核心优势
- **领域专业知识**：捕获为可重用指令和资源
- **可重复工作流**：多步骤任务转为一致流程
- **跨产品复用**：一次构建，多处使用

### 实践案例
[Codex 工程实践](sources/工程技术-在智能体优先的世界中利用-codex.md) 展示：
- "人类掌舵，智能体执行"模式
- 代码仓库作为记录系统
- 渐进式披露信息
- 规范架构与品味强制执行

## 第七阶段：环境工程（未来方向）

### 核心愿景
从上下文工程走向**环境工程**，构建持续演化、可感知、可交互的智能环境。

| 阶段 | 主要内容 | 特点与局限性 |
|------|----------|--------------|
| 提示词工程 | 设计单条高质量 Prompt | 静态、一次性、缺乏动态适应性 |
| 上下文工程 | 动态收集、组织和注入多模态上下文 | 关注模型输入，提升表现，但仍以模型为中心 |
| 环境工程 | 构建持续演化、可感知、可交互的智能环境 | 关注模型所处的世界，AI 主动塑造环境 |

### 为什么是终极目标
1. 环境包含动态变化的世界状态、规则、交互历史、反馈机制
2. AI Agent 不再被动接受上下文，而是主动感知、探索、影响环境
3. 强调 AI 与环境的双向作用，支持持续学习、自适应、协作
4. 输入输出不再局限于文本，而是包括真实世界的感知、动作和长期影响

## 演进路线总览

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        从提示工程到上下文工程的演进                        │
└─────────────────────────────────────────────────────────────────────────┘

第1阶段: 基础提示工程
  └── 词句优化 / zero-shot / few-shot / 最佳实践

第2阶段: 结构化提示词
  └── 模块化 / Role + Goals + Constrains + Skills + Workflow

第3阶段: 函数调用 + Agent 基础
  └── 工具调用 / ReAct / Agent Executor

第4阶段: Agent 设计模式
  ├── 规划类: Plan & Execute → REWOO → LLM Compiler
  └── 反思类: Basic Reflection → Reflexion → LATS

第5阶段: 上下文工程
  └── Write / Select / Compress / Isolate / 长时任务策略

第6阶段: Agent Skills
  └── 渐进式披露 / 模块化能力 / 开放标准

第7阶段: 环境工程 (未来)
  └── 主动感知 / 持续演化 / 双向交互
```

---

## 关键结论

1. **演进驱动力**：从"找到正确的词"到"配置正确的上下文"，从离散任务到长时运行，从单一智能体到多智能体协作。

2. **核心转变**：从优化单个提示词到管理整个上下文状态，从被动响应到主动规划，从静态指令到动态适应。

3. **实践建议**：
   - 初期：使用结构化提示词和最新模型
   - 中期：引入 Agent 架构和上下文管理策略
   - 长期：采用 Agent Skills 和渐进式披露设计

4. **未来方向**：环境工程将成为构建真正自主智能体的关键，AI 将从"被动工具"进化为"主动参与者"。
