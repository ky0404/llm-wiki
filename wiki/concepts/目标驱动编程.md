# 目标驱动编程

## 定义
目标驱动编程是一种编程方法论，强调将指令式任务转化为可验证的目标，让 LLM（或程序员）能够独立循环执行直到达成目标，而不是逐步指导具体操作。

## 要素
1. **成功标准**：明确定义什么是成功，而不是如何达到成功
2. **验证循环**：LLM 能够循环执行，每次迭代都验证是否满足成功标准
3. **声明式目标**：将"做什么"转化为"达到什么状态"
4. **可测试性**：每个目标都有明确的验证方法

## 应用
### 在 [[wiki/sources/CLAUDE]] 中
目标驱动执行是四个核心原则之一：
- **传统方式**："添加验证"（指令式）
- **目标驱动方式**："为无效输入编写测试，然后让它们通过"（声明式目标）

### 实际示例
| 指令式任务 | 目标驱动转化 |
|------------|--------------|
| "修复 bug" | "编写重现 bug 的测试，然后让它通过" |
| "重构 X" | "确保重构前后测试都能通过" |
| "添加功能" | "编写功能测试，然后实现功能使其通过" |

## 优势
1. **减少微管理**：不需要逐步指导具体实现
2. **提高自主性**：LLM 可以独立工作直到达成目标
3. **质量保证**：成功标准本身就是验证机制
4. **适应性**：LLM 可以选择最适合的实现路径

## 与 LLM 的关系
基于 [[wiki/entities/andrej-karpathy]] 的洞察：
> "LLM 非常擅长循环执行直到达成特定目标……不要告诉它该做什么，给它成功标准，然后看着它完成。"

这种方法特别适合 LLM 编码，因为 LLM 可以：
1. 理解高层次目标
2. 规划实现路径
3. 迭代执行直到满足成功标准
4. 自我验证结果
